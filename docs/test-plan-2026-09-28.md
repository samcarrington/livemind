# LiveMind test suite plan

- **Date:** 2026-09-28
- **Status:** proposed
- **Related:** [review-app-2026-09-28.md](./review-app-2026-09-28.md), [review-app-ledger.md](./review-app-ledger.md)

## 1. Why

LiveMind has no automated tests. The `app.py` decomposition (commit `7058efb`) was checked with throwaway side-by-side parity scripts. They were discarded afterwards, so the next change has no safety net. Nine review findings (R1-001 to R1-009) are open. None of them has a test that proves the defect exists, or that a fix works.

## 2. Objective and success criteria

**Objective:** a pytest suite that lets us refactor and fix defects with confidence. It must run locally and in CI with no external services.

The plan is done when all of the following hold:

| # | Criterion | How it's checked |
|---|---|---|
| S1 | `uv run pytest` passes on a clean checkout with no `.env`, no network, no GPU and no STT/LLM services | CI job with outbound network blocked (`pytest-socket`) |
| S2 | REST and WebSocket behaviour is characterised: every route in the route table has at least one test, and the WS message types in `CLAUDE.md` are covered | Route-table test (§5.3) fails if a route has no test module tag |
| S3 | `reconciler`, `db` and the pure helpers in `stt_worker` and `services/llm` have unit tests | Coverage report per module (reported, not gated) |
| S4 | Each of R1-001 to R1-009 has a regression test marked `xfail(strict=True)`; fixing a finding turns its test into an XPASS, which fails the run until the marker is removed | `tests/regressions/`, one test ID per finding, cross-referenced in the ledger |
| S5 | CI runs lint and tests on every push and PR to `main` | `.github/workflows/ci.yml` green |

**Out of scope for this plan** (possible later work):
- Browser and frontend tests.
- A coverage gate.
- STT/LLM accuracy evaluation.
- Load testing.

## 3. Current state: what makes this codebase hard to test

| Area | Problem | Consequence for tests |
|---|---|---|
| Module-level singletons | `services/runtime` (queues, clients, metrics, `reconciler`), `services/session_runtime.live_session`, `services/llm` (chain, breakers, `_last_serving_provider`), `stt_worker` (context and dedupe buffers), and `db._db` | State leaks between tests. A reset fixture is needed (§4.3). |
| Lifespan side effects | `lifespan` calls `check_ollama_models()`, which makes a network call, and starts `broadcast_loop` / `snapshot_loop` without ever cancelling them | `TestClient(app)` reaches the network and leaves tasks running. A small seam is needed (§4.4). |
| `.env` auto-load | `settings.py` loads `.env` at import time | A developer's real API keys would be picked up, so tests could make paid calls. Env must be scrubbed before import (§4.2). |
| `db.DB_PATH` read at import | The path is fixed when `db` is first imported | Set `DB_PATH` before importing `app`, or call `db.init_db(tmp_path)` directly. |
| Wall-clock time | `reconciler` uses `time.time()` for decay and churn | Decay tests need a controllable clock (monkeypatch `reconciler.time`). |
| Mixed HTTP clients | aiohttp is used in `services/llm` and `routes/post_session`; `requests` is used in `stt_worker` and `routes/providers` | Fakes are needed for both (§4.5). |
| Stale `requirements.txt` | Still lists Mac-only `sounddevice`, `moshi_mlx` and `sentencepiece`; `pyproject.toml` + `uv.lock` are the real manifest | CI uses `uv sync` only. Deleting `requirements.txt` is a separate decision. |

## 4. Foundations (Phase 0)

### 4.1 Tooling

Add a dev dependency group through uv (no changes to runtime dependencies):

```bash
uv add --dev pytest pytest-asyncio httpx aioresponses responses pytest-socket pytest-cov ruff
```

Add to `pyproject.toml`:

```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
asyncio_mode = "auto"
addopts = "-ra --strict-markers --disable-socket --allow-unix-socket --allow-hosts=127.0.0.1,localhost"
markers = [
  "unit: pure, no I/O",
  "integration: app/db/ws with fakes",
  "regression: reproduces an open review finding",
  "docker: needs a docker daemon (CI only)",
]
xfail_strict = true
```

Add Makefile targets `test` (`uv run pytest -m "not docker"`) and `lint` (`uv run ruff check .`).

### 4.2 Environment isolation (`tests/conftest.py`, top of file, before any app import)

- Remove every provider key and URL from `os.environ`: `ANTHROPIC_*`, `GEMINI_*`, `HUGIN_*`, `OLLAMA_*`, `STT_*`, `PARAKEET_URL`, `CANARY_URL` and `DB_PATH`.
- Point `DB_PATH` at a per-session temp file.
- Stop `.env` from loading: either add a `LIVEMIND_NO_DOTENV=1` guard in `settings.py` (a one-line, behaviour-neutral seam), or chdir into a temp directory during import.
- `pytest-socket` is the backstop: any real outbound call fails the test loudly.

### 4.3 State reset fixture (autouse)

Reset every singleton to its initial state before each test:

- `live_session`: fields back to the values set in `SessionState.__init__`.
- `runtime`: clear the queue, clients, activity log and metrics.
- `reconciler`: fresh `Reconciler()`, swapped in place wherever it is imported.
- `llm`: chain and breakers back to their defaults.
- `stt_worker.reset_state()`.
- `post_session.clean_jobs.clear()`.

If this fixture ends up long, that is evidence for the `app.state` injection follow-up. Record it in the ledger instead of working around it.

### 4.4 App fixtures and minimal seams

- `app_client`: Starlette `TestClient(app)` used as a context manager, so the lifespan runs. This client covers both REST and WS.
- `async_client`: `httpx.AsyncClient(transport=ASGITransport(app))`, for tests that need to await background work.
- Seams needed. Each one is behaviour-neutral and gets its own commit:
  1. Lifespan: keep the created loop tasks and cancel them on shutdown. This also fixes a real leak.
  2. Make `check_ollama_models` patchable. It already is, as a module attribute; the fixture monkeypatches it to a no-op.
  3. A test-only clock hook for `reconciler`: either a `now` parameter defaulting to `time.time`, or monkeypatching `reconciler.time.time`. Prefer monkeypatching unless tests become awkward.

### 4.5 Fakes (`tests/fakes/`)

| Fake | Replaces | Default behaviour | Controls |
|---|---|---|---|
| `FakeLLM` | `services.llm._call_provider` (seam) and aiohttp calls via `aioresponses` (adapter tests) | Returns a canned graph JSON | Per-provider success/failure/timeout; a delay gate (`asyncio.Event`) |
| `FakeSTT` | `stt_worker._transcribe_backend` (seam) and `requests` via `responses` (adapter tests) | Returns fixed text | Blocking gate to reproduce R1-007; hallucination strings |
| Audio fixtures | none | Base64 PCM of silence plus a 440 Hz tone at 48 kHz, generated with numpy in a fixture | Duration and sample rate |

Rule: route and pipeline tests fake at our own seams (`_call_provider`, `_transcribe_backend`). Only adapter contract tests (§5.4) fake at the HTTP layer. That keeps most tests independent of provider wire formats.

**Phase 0 exit:** `uv run pytest` runs one smoke test (`GET /` returns 200 through the lifespan) with sockets disabled and no `.env`, and CI is green.

```
tests/

  fakes/                   fake_llm.py, fake_stt.py, audio.py
  unit/                    test_reconciler.py, test_stt_helpers.py, test_llm_parsing.py,
                           test_circuit_breaker.py, test_pricing.py, test_settings.py
  db/                      test_schema_and_migrations.py, test_sessions_crud.py, test_recaps.py
  api/                     test_route_table.py, test_pages.py, test_sessions_api.py,
                           test_post_session_api.py, test_providers_api.py
  ws/                      test_ws_protocol.py, test_ws_restore.py
  pipeline/                test_audio_pipeline.py, test_llm_proxy.py, test_clean_jobs.py
  contracts/               test_ollama_adapter.py, test_gemini_adapter.py,
```

### 5.1 Unit (Phase 1)

- **`reconciler`** (highest value; it is pure logic):
  - Scoring weights (0.45 recency / 0.35 frequency / 0.20 centrality + pin bonus).
  - The `MAX_ACTIVE=24` budget.
  - Decay to parked at 720 s, using a controlled clock.
  - Every `apply_action` type.
  - `clamp_positions`.
  - Churn metrics.
  - A `get_full_state` / `load_state` round-trip.
  - A property-style loop over random proposals: active nodes never exceed 24, and edges never reference missing nodes.
- **`stt_worker` helpers:**
  - `_clean_whisper_output` against a table of known hallucinations.
  - `_is_duplicate` and the context window.
  - `_resample`: length and dtype for 44.1k, 48k and 16k inputs.
  - `configure_stt` / `get_stt_config`.
- **`services/llm`:**
  - `extract_graph_json` on fenced, prefixed, truncated and invalid output.
  - `validate_tier`.
  - Pricing maths.
  - Circuit breaker transitions: closed → open after 3 failures → backoff capped at 60 s → half-open → closed.
- **`settings`:** default values when the env is empty; the `VALID_PROVIDERS` membership check.

**Exit:** the modules above have tests. Coverage is reported (target around 80% on `reconciler.py`, but not gated).

### 5.2 Persistence (Phase 1, in parallel)

- Against a real SQLite file in `tmp_path` (not mocked):
  - Schema creation.
  - WAL mode.
  - Migrations applied to an old-schema fixture DB.
  - CRUD for sessions, segments, snapshots, actions, recaps and synthesis.
  - Archive, unarchive and delete, including cascades.
- `get_segments_since` boundary conditions; latest-snapshot ordering.

### 5.3 API and WebSocket characterisation (Phase 2)

This replaces the throwaway parity scripts (`/tmp/lmref/parity.py`, `verify_routes.py`, `ws_paths.py`) with permanent tests.

- **`test_route_table.py`:**
  - Snapshot of `(method, path, endpoint name)` for all 37 routes.
  - An explicit precedence assertion: `/v1/sessions/synthesis` resolves to the synthesis handler, not `/{session_id}`.
  - Every route has at least one test that exercises it (enforced with a `@covers_route("GET /v1/...")` marker).
- **Sessions:**
  - new → segments → end → detail → export status.
  - Restore via `connect_session` with `last_seq`.
  - Each action type through `session_action`.
- **Post-session** (with `FakeLLM`): recap generate/get, synthesis CRUD, clean-transcript job lifecycle and progress polling.
- **Providers:** `GET/POST` for active LLM and STT; invalid provider → 4xx; `/v1/metrics` shape.
- **WS protocol:**
  - Every message type in `CLAUDE.md`: ping, get_metrics, claude_request, connect_session, frontend_metrics, audio_chunk.
  - Assert the server → client message shapes: transcript, partial_transcript, claude_response, graph_update, restore, session_reset, status, metrics.
  - A schema helper validates the required keys per message type.

**Exit:** criterion S2 is met.

### 5.4 Pipeline and adapter contracts (Phase 3)

- **Audio pipeline:** audio_chunk over WS → `FakeSTT` → transcript broadcast to a second connected client → segment persisted with the correct seq.
- **LLM proxy:** claude_request → chain → reconciled graph → `claude_response` broadcast → metrics updated.
- **Fallback:** primary fails → secondary serves → `get_last_serving_provider()` reports it.
- **Breaker:** the breaker opens and skips the provider.
- **Clean jobs:** progress reaches done; a failure is reported as an error state.
- **Adapter contracts** (`aioresponses` / `responses`): request URL, headers, body shape and response parsing for each of Ollama, Gemini, Anthropic, faster-whisper, Parakeet and Canary. Include error and timeout mapping. These are the only tests that know provider wire formats.

### 5.5 Regression tests for review findings (Phase 4)

All live in `tests/regressions/test_review_findings.py`. Each test is marked `@pytest.mark.regression`, uses `xfail(strict=True, reason="R1-00N open")`, and is named `test_r1_00N_*`.

Behavioural findings assert the correct behaviour, so they fail today. Structural findings (R1-004/005/006) have no single observable defect. For those, the test asserts the agreed target boundary, so the xfail marks the refactor as done.

| Finding | Test (asserts the fixed behaviour) | Technique |
|---|---|---|
| R1-001 | Ending a session that is not the current one leaves the live graph and `live_session` untouched, and persists nothing under the other ID | Create A (current) and B; `POST /v1/sessions/B/end`; assert that A's runtime state is intact and no snapshot for B contains A's nodes |
| R1-002 | Session REST routes and `/ws` reject unauthenticated requests; `/ws` rejects a foreign `Origin` | Parametrise over the sensitive routes; expect 401/403 and a WS close. **Needs the auth decision first**; until then the xfail reason is "auth design pending" |
| R1-003 | No outbound call disables TLS verification | Two parts: an AST scan of `services/`, `routes/` and `stt_worker.py` for `ssl=False` / `verify=False`; plus fakes that capture the `ssl`/`verify` kwarg on each adapter call |
| R1-004 | Session reset lives in one place and uses only the reconciler's public API | Assert `Reconciler.reset` exists and that an AST scan finds no `reconciler._*` access outside `reconciler.py`. The decomposition has already fixed the duplication part |
| R1-005 | Graph processing is callable without a WebSocket or broadcast | Assert a service function (e.g. `llm_graph.process(body) -> result`) exists and runs with `FakeLLM` and zero connected clients, with nothing broadcast |
| R1-006 | Recap and synthesis run as services, independent of any `Request` | Assert `services.post_session.generate_recap(session_id)` and `generate_synthesis(ids)` exist and work with `FakeLLM` |
| R1-007 | A transcription finishing after a session reset does not write into the new session | Hold `FakeSTT` on a gate; send an audio_chunk; reset the session; release the gate; assert the new session has no segments and nothing was broadcast |
| R1-008 | `session_action` for a non-current session does not mutate the live graph | Current is A; POST an action for B; assert the live reconciler state is unchanged |
| R1-009 | Oversized and flooded WS input is bounded | Oversized `audio_chunk` → error/close; N concurrent `claude_request` → at most K in flight (K from settings); the queue has a maximum size |

When a finding is fixed:
1. Remove the xfail marker in the same PR.
2. Update the ledger row to `fixed`, with the test ID.

The strict xfail enforces step 1: leaving the marker on turns the run red.

**Exit:** criterion S4 is met. The ledger gains a `Test` column pointing at each test ID.

## 6. CI

`.github/workflows/ci.yml`, run on push and PR to `main`:

1. **`lint`:** `uv sync --dev`, then `uv run ruff check .`. Start with the rule set `ruff check` passes today; tighten later.
2. **`test`:** `uv run pytest -m "not docker" --cov --cov-report=term-missing`, on Python 3.12, with no secrets configured.
3. **`image`:** `docker build`, then `uv run pytest -m docker`. It can run after `test`, and on PRs that touch `Dockerfile`, `*.py`, `routes/` or `services/`.

Keep the suite fast: target under 30 s for everything except the `docker` marker. Tests never sleep on real time: use gates/events, and patch `asyncio.sleep` in the loops if needed.

## 8. Risks

| Risk | Likelihood / impact | Mitigation |
|---|---|---|
| **Top risk: shared singletons and uncancelled background loops make tests order-dependent and flaky** | High / High | Autouse reset fixture; lifespan seam that cancels loops; run with `pytest -p randomly` in CI once stable; treat any flake as a bug |
| Tests accidentally call paid APIs using a developer's `.env` | Medium / High | Env scrub before import, dotenv guard, `pytest-socket` blocking non-localhost |
| Characterisation tests lock in current bugs | Medium / Medium | Known-wrong behaviour goes in `regressions/` as xfail, never as a passing assertion |
| Structural regression tests (R1-004/005/006) prescribe a design before it is agreed | Medium / Low | Keep the asserted function names provisional in the xfail reason; adjust them when the design decision is made |
| R1-002 cannot be written until auth is designed | High / Low | Ship it as xfail "auth design pending"; open a design task |
| Seams added for testing change behaviour | Low / Medium | Each seam lands in its own commit, with the characterisation tests from Phase 2 run before and after |
