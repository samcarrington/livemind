Decision (design): Modularise the 2,543-line LiveMind FastAPI app by responsibility while preserving the root app.py launch/compatibility entry point and existing HTTP/WebSocket contracts. Separate route groups into routes/pages.py (static HTML/assets), routes/sessions.py (session CRUD/lifecycle/actions/restore/snapshots/exports), routes/post_session.py (recap/synthesis/transcript-clean endpoints), routes/providers.py (LLM/STT provider and metrics endpoints), and routes/live.py (WebSocket protocol). Separate services into services/llm.py (provider adapters, fallback/circuit breaker, usage and graph-response parsing), services/session_runtime.py (session/generation/sequence ownership and lifecycle/reset coordination), services/post_session.py (post-session workflows and job state), and services/live_pipeline.py (audio tasks, LLM graph ingestion, broadcasts and snapshots). app.py remains responsible for app construction, shared runtime setup, router registration, lifespan, and compatibility exports needed by replay.py. Inject shared runtime through app.state/router dependencies rather than importing mutable globals from app.py. Leave db.py, reconciler.py, and stt_worker.py as existing boundaries. Extract incrementally with behavior-characterization tests. Rationale: group by cohesive responsibility and isolate risky stateful workflows while keeping framework wiring and public contracts stable. Rejected alternative: a big-bang rewrite, one generic utils.py, or one module per endpoint; these either create unnecessary coupling/risk or fragment related workflows without reducing architectural coupling.
